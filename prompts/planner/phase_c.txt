## Phase C — Define stages from decisions

Using the decisions identified in Phase B, define stage boundaries. The decisions ARE the GT — do not search for new GT here.

**Boundary rule:**
- For icd_procedure decisions at event index K: the preceding stage ends at K-1 (D is just outside visible range). Use get_events_by_index to confirm K-1 is a real event.
- For note_section decisions (medication holds/restarts with no specific index): estimate when clinically it occurred. Call get_events_by_index on the relevant time window to find the actual event cluster. A medication hold at admission ends Stage 1 around the first major monitoring event (not an arbitrary index). A medication restart near discharge means the stage before it spans most of the post-procedure monitoring.
- Minimum stage size: each stage must span at least 5 events. If a proposed stage spans fewer, merge it with an adjacent stage.
- Verify boundaries with get_events_by_index before committing. Do not set boundaries at events 57, 58, 59 unless you confirmed what is actually at those indices.
- The next stage starts at K and treats D as past context

**Stage structure:**
- Stage 1 starts at index 0
- Each new stage starts where the previous stage's GT decision occurs
- Final stage (Discharge): starts after the last non-discharge decision, ends at total_events-1, GT = all discharge ICD diagnoses

**For each stage, write:**
- label: "Initial Presentation", "Inpatient Management", or "Discharge Planning" (generic — no clinical content in the label)
- index_range: [start, end]
- decision_required: the specific clinical question whose answer IS the GT. Must align with the GT:
  - If GT = endoscopy → "What diagnostic procedure should be performed to evaluate [symptom]?"
  - If GT = medication hold → "Should [drug class] be held given [clinical situation]?"
  - If GT = medication restart → "Is it appropriate to resume [drug class] given [clinical situation]?"
  - If GT = discharge diagnoses → "List all diagnoses established or actively managed during this admission."
- available_agents: patient (stage 1 and when new symptoms drive decisions), nurse (vitals/meds/procedures), lab (lab results needed), history (prior admissions relevant)
- trigger: one sentence describing what opens this stage (patient for stage 1; nurse for later stages — describe the transition event only, never the finding or GT answer)
- gt: the decision(s) identified in Phase B for this stage, written as structured dicts (same format as Phase E):
  - `{"type": "procedure", "index": N, "icd_code": "...", "icd_version": 9|10, "display": "..."}`
  - `{"type": "diagnosis", "icd_code": "...", "icd_version": 9|10, "display": "..."}`
  - `{"type": "medication", "index": N, "drug": "..."}`
  - `{"type": "plan", "section": "...", "span": "..."}`

**Medication GT rule:** Only cite a medication as GT (Tier 3 / source: "medication") if it appears for the FIRST TIME in the admission at an index > stage end. Medications already visible in prior events are not new decisions — use note_section instead to describe the hold/restart decision.

**Discharge GT rule:** Include only ICD diagnoses that were actively treated or managed during this admission. Call get_diagnoses if you have not already, then EXCLUDE:
- Personal history codes (Z86xxx, Z87xxx, Z85xxx)
- Device/implant presence codes (Z93xxx, Z96xxx, Z95xxx)
- External cause codes (Yxxx, Exxx)
- BMI codes (Z68xxx)
- Unspecified place/activity codes (Z929, Y929)
- Lab-finding-only codes (e.g. R8271 CRP elevated) — these are measurements, not physician decisions
Include: primary diagnoses, procedure-related diagnoses, comorbidities that required medication adjustment or new treatment during this admission.

List all stages with their proposed GT before proceeding to Phase D.
