## Phase C — Build stages from information-decision cycles

Using the cycles from Phase A and the confirmed GT indices from Phase B, construct the stages.

---

### Splitting rule

Each cycle from Phase A becomes one stage. The stage range = the information part of the cycle.

```
Cycle:  Info [index 0..K−1]  →  Decision at index K
Stage:  index_range = [0, K−1],  gt = decision at K
```

**Same information, multiple decisions** (no new information between them):
```
Info [0..K−1]  →  Decision A at K  →  Decision B at K+2  →  Decision C at K+5
Stage:  index_range = [0, K−1],  gt = [A, B, C]
```
Range ends before the FIRST decision. All decisions from this information block are GT items.

**New information produces next cycle:**
```
Info₁ [0..K−1]  →  Decision₁ at K  →  Info₂ [K..M−1]  →  Decision₂ at M
Stage 1:  index_range = [0, K−1],  gt = Decision₁
Stage 2:  index_range = [K, M−1],   gt = Decision₂
```

For plan GT (no index): place it in the stage whose information context made the decision necessary.

---

### Structure rules

- Stage 1 always starts at index 0
- Stages are contiguous: each stage starts where the previous one ends + 1
- Final stage ends at total_events − 1, GT = discharge diagnoses
- Every stage must have at least one GT item
- Avoid stages with fewer than 5 events — merge with the following stage if needed

---

### Discharge GT

Call get_diagnoses. Include diagnoses in ANY of these categories:
- **Primary admission diagnoses**: the condition(s) that caused this admission, including surgical indications (e.g. tarsal tunnel syndrome, femur fracture, NSTEMI). Keep even if the surgery was pre-planned — the surgical indication is still the primary reason for admission.
- **Procedure-related diagnoses**: conditions directly addressed by a procedure performed this admission.
- **Active complications or new findings**: conditions that arose during admission and required a physician response (e.g. hypotension, rash, AKI, arrhythmia).
- **Comorbidities actively managed**: conditions that required a new treatment decision or significant monitoring adjustment during this admission.

Exclude:
- Personal history (Z85x, Z86x, Z87x), device/implant presence (Z93x, Z95x, Z96x)
- Long-term drug use (Z79x), BMI (Z68x)
- External cause codes (Yx, Ex, Vx), unspecified place (Y929, Z929)
- Lab-value-only R codes
- Background comorbidities with no active management this admission (e.g. hypertension, GERD, anxiety listed for billing only)

---

### For each stage, write

- **label**: generic description, no clinical content that reveals the GT (e.g., "Initial Presentation", "Inpatient Management", "Pre-Discharge")
- **index_range**: [start, end]
- **available_agents**: patient (stage 1 and new patient-reported symptoms), nurse (vitals/meds/observations), lab (labs/imaging), history (prior admissions)
- **trigger**: one sentence — the event that opens this stage (the handoff or transition, never the GT answer). Use patient agent for stage 1; nurse for later stages.
- **gt**: list of GT dicts — one item per distinct decision. For plan GT, one span per decision. For medication GT, use the correct action: "start" (new drug, needs index), "stop" (held/discontinued, no index), "increase_dose", "decrease_dose". Never use plan GT for medication decisions.
